# session-tag 設計書

## 目的

セッションが増えると、各セッションが何の作業だったかが分からなくなる。完了して不要なセッションも、判別できない。

`session-tag` は、現在のプロジェクトのセッションにタグを付けて一覧表示する mod である。利用者は、一覧を見て、内容と完了の状態を判断できる。

## ゴール

- `/session-tag` で、現在のプロジェクトのセッションの一覧をペインに表示する。
- 各セッションに、作業内容を表す内容タグを自動で付ける。
- 利用者が、一覧で選んだセッションに完了タグを付ける。外すこともできる。
- タグは、セッションをまたいで保持される。

## ノンゴール

- セッションの削除。削除は `session-rm` の役割である。この mod は `session-rm` と連携しない。
- 他のプロジェクトのセッションの表示。
- 完了タグの自動判定。完了の定義は、利用者の判断に任せる。
- 常時表示のペイン。ペインは `/session-tag` を打ったときだけ開く。

## アンチゴール

- セッションの本体ファイル(`.jsonl`)を変更すること。
- 確認なしに、1回で大量のモデル呼び出しを行うこと。

## 利用者の決定事項

- 内容タグは自動、完了タグは手動で付ける。
- 起動は `/session-tag`。ペインはコマンドを打ったときだけ開く。
- 内容タグは、ペインを開いたときに、タグのないセッションへまとめて付ける。1回に最大20件とし、新しい順に処理する。
- 一覧は、現在のプロジェクトのセッションだけを対象にする。
- 完了タグは、ペインの一覧でセッションを選んで付ける。

## 構成(調査で確認した事実)

- 構成は `mods/session-rm` に合わせる。`$.command.register`、`$.ui.open`、`Select` を使う。
- セッションの一覧は、`~/.claude/projects/<cwd を `-` に置換した名前>/<id>.jsonl` を `$.fs.list` で読む。先頭 64 KiB を `head -c` で読み、最初のユーザープロンプトを取り出す。
- 内容タグの生成は、`$.model.complete({ model: "haiku", prompt })` を使う。
- タグの保存は、`$.store`(JSON、全体で 4 MiB まで)を使う。

## builder に任せる事項(設計者の判断)

- mod 名は `session-tag`。コマンドも `/session-tag`。
- 保存の形式。キーはセッション ID。値は `{ tag, done }`。
- 内容タグの形式。日本語または英語の短い語句で、20 文字以内。プロンプトは builder が決める。
- 一覧の表示形式。日付、完了マーク、内容タグ、先頭プロンプトの一部を 1 行に出す。
- 現在のセッションも一覧に出す。完了タグは付けられない。(判断: 作業中のセッションに完了タグは意味がない。)
- 完了タグの切り替え。選んだセッションの完了状態を反転する。確認は出さない。
- ペインの文言とコマンドの説明は、英語にする(既存 mod の方針に合わせる)。
- バージョンは 0.1.0。README(`README.md`、`README.ja.md`)と `types/index.d.ts` を付ける。
- 内容タグの生成に失敗したセッションは、タグなしのまま残す。次にペインを開いたとき、再試行する。

## builder check で追加した決定

回答済み(既存コードで確認した):
- プロジェクトのディレクトリ名は、cwd の英数字以外の全文字を `-` に置換した名前である。`mods/session-rm/hooks/register.tsx` の `paths` と同じ規則を使う。mod 間で共有できないため、コードは複製する。
- 現在のセッション ID は `$.session.id()` で得る。
- 外部コマンドは `$.process.run` で実行する。`session-rm` が同じ方法で `head` を実行している。

設計者の判断(利用者が確認できる):
- `/session-tag` の実行を、モデル呼び出しへの同意とみなす。確認は出さない。
- ペインはすぐに開く。一覧は先に表示し、内容タグは 1 件ずつ生成が終わるたびに更新する。生成中は「Tagging n/m」を表示する。
- 対象は「タグのない最新 20 件」とする。タグ済みのセッションは数えない。生成に失敗した件も 20 件に数える。失敗した件は、次にペインを開いたとき再試行する。
- 最初のユーザープロンプトの取り出しは、`session-rm` の `firstPrompt` と同じ規則とする。途中で切れた行と `<` で始まる行は飛ばす。取り出せないセッションは「(no prompt)」と表示し、モデルを呼ばない。保存はせず、20 件の枠にも数えない。次にペインを開いたとき、もう一度確認する。(実装中に変更した。進行中の別セッションが、「(no prompt)」のまま固定されるのを防ぐため。)
- ペインを開くとき、`.jsonl` が存在しないセッションの保存エントリを削除する。`$.store` の上限(4 MiB)を超えないためである。
- 現在のセッションを選んだときは、何も起きない。一覧には「(current)」と表示する。

## 未確認の事項

- `$.model.complete` の実際の遅延と費用。20 件の逐次呼び出しの所要時間は、実装後に測る。
- 実機での動作確認は、実装後に行う。
